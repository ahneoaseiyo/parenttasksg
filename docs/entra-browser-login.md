# Browser Entra External ID login — PKCE primitives (not wired to UI)

`src/entraBrowserAuth.js` provides an opt-in, browser-only authorization-code + S256 PKCE foundation. It generates cryptographically random state, nonce and verifier; stores only the short-lived authorization transaction in tab-scoped sessionStorage; removes the transaction before validating the callback; rejects stale or mismatched callbacks; and exchanges a code for an API access token. Returned access tokens must be held **in memory only** and never logged or persisted in localStorage/sessionStorage.

**This is not a completed login feature.** The existing prototype UI still uses demonstration navigation. The module is not yet wired to routing or API calls. The returned ID token is not validated, the nonce is not yet checked against an ID-token claim, and logout/session renewal are not implemented. Do not use this as proof of authenticated user identity. API access tokens are independently validated by the backend, including signature, audience, issuer and the school-controlled active identity registry.

Before wiring real sign-in: create an external tenant, register a SPA and a separate API, enable Authorization Code + PKCE, configure an exact redirect URI and API scope, implement callback route and error states, ensure nonce validation through a reviewed OIDC client, implement memory-only access-token lifecycle and logout, and verify browser security headers. Prefer a well-maintained Microsoft authentication SDK for the complete interactive sign-in flow rather than hand-maintaining protocol details. No production approval or child data is implied.
